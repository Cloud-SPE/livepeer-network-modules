# Manifest schema changelog

Schema changes are cross-cutting and force a spec-wide SemVer bump (per
[`PROCESS.md`](../PROCESS.md)).

| Spec version | Date | Change |
|---|---|---|
| 2.4.1 | 2026-08-26 | No shape change. `spec_version` now has one Go source, `version.VERSION` (`livepeer-network-protocol/version`), tested against `VERSION`; brokers stamp it on `GET /registry/offerings` and the coordinator refuses to merge brokers on a different major (`protocols/broker-admin.md` §7). `session.session_params_schema` description repointed from the retired `paid-session` §7.1.1 describe path to the runner attach contract (`protocols/runner-attach.md`), which is now the only way runner facts reach a tuple — via the offer freeze, never live. |
| 0.1.0 | 2026-05-06 | Initial draft. Two-field outer envelope (`manifest` + `signature`). Manifest payload carries `spec_version`, `issued_at`, `expires_at`, `orch.{eth_address, service_uri?}`, and a flat `capabilities[]` array. Each capability tuple has `capability_id`, `offering_id`, `interaction_mode` (e.g. `http-stream@v0`), `work_unit.name`, `price_per_unit_wei` (string-encoded big int), `worker_url` (HTTPS), optional `extra`, optional `constraints`. No `capacity` field — workers signal saturation via 503 + `Livepeer-Backoff`. Signature is secp256k1 over the JCS-canonicalized (RFC 8785) form of the manifest payload. |
| 0.2.0 | 2026-05-06 | Add `publication_seq` (non-negative integer, required) to the inner manifest payload. Each cold-key signature emits a value strictly greater than every previously-signed value for the same `eth_address`. Resolvers cache the last-seen value per `eth_address` and reject manifests with `publication_seq <= last_seen`, closing the rollback gap inside the `(issued_at, expires_at)` window. Pre-1.0.0 minor bump per `PROCESS.md`. |
| 2.4.0 | 2026-08-22 | Add optional `work_unit.estimator` to the capability tuple: how a CLIENT computes a funding ceiling before the work runs, with required `id`, `rounding` and `exactness` and optional `package` and `fixtures`. This is the one exception to extractors being unadvertised — how a seller counts is otherwise its own business — and it exists because a buyer reserving funds against a measurement it cannot derive from its own request is guessing. A JSON workload exposes its ceiling in its own parameters; a multipart upload does not, so the caller and the seller would reach two different numbers. A consumer MUST refuse an `id` it does not implement rather than estimate. Additive and backward-compatible: absent means the caller can derive the ceiling itself, which is the case for most offerings. |
| 2.3.0 | 2026-08-20 | Add optional `settlement_keys[]` to the manifest payload: hot keys the orch's cold key delegates settlement signing to, each with a validity window. A broker is network-exposed and must never hold the cold key that anchors the operator's on-chain identity, so it signs settlement records with a delegated key instead; the cold key's signature over this block is what makes that key trustworthy. All currently-valid keys are listed, so a record signed just before a rotation still verifies. Additive and backward-compatible. |
| 2.2.0 | 2026-08-20 | Add optional `session.max_rotations` (integer ≥ 0, absent or 0 means the default 3): the bound on rebinding a session onto a rotated payment identity, per `protocols/paid-session.md` §3.3.1. Additive and backward-compatible. |
| 2.1.0 | 2026-08-20 | Add optional `per_units` (integer ≥ 1, absent means 1) to the capability tuple: the denominator of `price_per_unit_wei`, without which no offering can price below 1 wei per unit. Additive and backward-compatible — a 2.0.0 manifest reads identically, since absent means 1. See `protocols/offering-axes.md` §6 for the pair and the cumulative ceiling billing rule every layer computes. |
| 2.0.0 | 2026-08-19 | **Breaking.** `interaction_mode` removed; replaced by required `protocol` (`<name>/v<major>`, e.g. `paid-job/v1`) plus a matching declared-axes object: `job.transports` for paid-job offerings, `session.{descriptor_schema, attachment, metering, refill, heartbeat, lease, tolerance_band_pct, runway_increment_units}` for paid-session offerings. Conditional rules pair each protocol with its axes object and forbid the other. Workload identity moves out of the protocol name into `session.descriptor_schema` (see `protocols/offering-axes.md`). Major bump: pre-2.0 consumers cannot read these manifests and 2.x consumers reject `interaction_mode`. Note `spec_version` carries the spec-wide version from `VERSION`, not a per-schema counter. |
