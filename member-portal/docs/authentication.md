# Durable portal sign-in

The portal uses EIP-191 wallet signatures over an origin-bound message containing
wallet, random nonce and five-minute expiry. The message explicitly separates
sign-in from regional membership. Challenges are single-use even on invalid
signatures; concurrent verification has one winner. Per-wallet and direct-peer
IP limits allow five challenges per minute. Forwarded IP headers are not trusted.
A reverse proxy may additionally rate-limit at the public edge.

Successful login sets a 24-hour Secure, HttpOnly, SameSite=Strict opaque cookie.
Only its SHA-256 hash is stored. Mutations require the exact configured HTTPS
Origin and Host. Bolt transactions persist nonce consumption, sessions and
logout across ordinary restarts. The state store is bound to the portal origin;
for a domain migration invalidate portal sessions with a fresh store explicitly.
Regional immutable pool IDs and books do not change. Expired authentication
records are removed every minute.

For each allowlisted regional request the server loads its protected Ed25519
issuer key and creates a wallet/pool/session-scoped token lasting at most two
minutes (also capped by the session expiry). Tokens remain server-side. Regional
controllers verify locally using their public issuer trust files; they never
call the portal. Logout prevents further issuance. Previously issued tokens
expire within two minutes; adding the session hash to regional trust
`revoked_sessions` permits immediate rejection. Existing running agents use
their own enrollment credentials and do not depend on portal availability.

Generate keys through the local image, mounting a writable private directory:

```sh
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD/local:/keys" \
  livepeer-member-portal:local --generate-key /keys/issuer.json \
  --trust-output /keys/member-trust.json --issuer https://members.example.org \
  --key-id portal-2026-01
```

The command never overwrites existing files. Keep the private key owner-readable
only and distribute only `member-trust.json` to regional controllers. Keys have
a one-year validity by default. Rotate before expiry: generate a new key pair,
publish both public keys in each regional trust file, then atomically replace
the portal's protected signer file. After the two-minute token lifetime, remove
or revoke the old public key. Failed trust/key reads fail closed. Back up the
protected key and portal state separately from regional accounting stores.

Configuration (immutable IDs are those generated by each controller):

```yaml
listen: "0.0.0.0:8090"
public_origin: https://members.example.org
state_path: /var/lib/member-portal/state.db
signer_file: /etc/member-portal/issuer.json
regions:
  - pool_id: pool_actual_eu_id
    name: EU
    url: https://eu-members.example.org
    ca_file: /etc/member-portal/service-ca.pem
  - pool_id: pool_actual_us_id
    name: US
    url: https://us-members.example.org
    ca_file: /etc/member-portal/service-ca.pem
```

The HTTPS client verifies certificates, pins the configured origin, refuses
redirects and ignores ambient HTTP proxy settings. Failed or oversized regional
responses are unavailable results, never zero balances. Browser responses are
non-cacheable; a qualified reporting cache is a separate presentation concern.
A graceful restart closes the store after HTTP shutdown. For manual restore,
stop the portal, restore a consistent stopped-store backup and protected signer,
then restart; restoring old sessions may resurrect logged-out sessions, so use
a fresh portal store after a security incident and revoke affected regional
session hashes or the old signing key. No automatic recovery is provided.
