# Assignment containers and model caches

A catalog `runner_compose` can include `companions`. These are containers in
one assignment, with one ownership generation and one drain/stop decision.
Only the primary runner on port 8080 is discovered and attached to the broker.
The agent retains the whole group while draining and removes the whole group
when the controller issues `stop`. A control-plane outage does not stop it.

The primary's `gpu` defaults to true. Set it false for a protocol proxy and
set a companion's `gpu: true` for the local model engine. Every GPU-enabled
container receives the assignment's device UUID; the renderer never gives
an NVIDIA container all host GPUs. Intel containers map only the inventoried
`render_node` to `/dev/dri/renderD128` and add its numeric `render_node_gid`.
Missing or malformed device inventory blocks rendering; the whole `/dev/dri`
directory is never granted to an Intel runner. The trusted inventory agent
has a read-only `/host-dev` metadata view to report the host's device group.
Image maps use the same vendor/class
selection and validation as primary images. Companion names are unique,
with `main` reserved for the primary. Companions cannot nest.

Environment and command values can reference `{{service.main}}` or
`{{service.NAME}}`; the controller resolves these to assignment-specific
Compose service names. Unknown references fail catalog validation. Values
are quoted and Compose dollar interpolation is escaped. They are catalog
literals, not member environment passthroughs. `command` supplies arguments
to the image's entrypoint; it does not replace that entrypoint.

`caches: {models: /models}` mounts a named volume. Names are scoped by the
assignment and the enrollment's Compose project. Reusing a logical cache
name within one assignment shares that volume; different assignments do not
share it. Mount targets must be clean absolute paths, cannot overlap, and
cannot mask `/dev`, `/proc`, or `/sys`. `shm_size_bytes` optionally sizes a
container's private shared-memory filesystem without host IPC access.

The primary depends on its companions starting. This is not a model-readiness
claim: runner self-description and broker certification still gate routing.
All containers use the existing enrollment-local Docker network; no engine
port is published on the host. Containers within that enrolled host's runner
network remain mutually reachable, as before. Docker socket access already
makes the member agent a trusted host administrator.

Normal `compose up`, removal and `compose down` preserve named caches. Do not
use `down -v` or prune volumes during recovery. Model caches can be reconstructed
from model sources, but a cold restart may need network access and substantial
time. Record cached model revisions when validating a rollout. A runtime can
also use these persistent mounts for its operation journal: those volumes are
required recovery state and must be backed up, unlike reconstructible model
weights. Control-plane financial and ownership databases have separate volumes.

The controller's `Models` field remains descriptive metadata. The runtime
loads/downloads its model into the mounted cache; the agent does not interpret
model repositories or pretend to report download progress. See the
[regional runtime definitions and validation limits](../../infra/scenarios/regional-pools/runner-readiness.md).

## Assignment-local secrets

`secret_env: [MASTER_KEY, BROKER_TOKEN]` declares environment names whose values
are generated by the member agent. Each value is an independent random 256-bit
base64 string, persisted by enrollment and assignment in the private
`runner-secrets/` directory next to the generated Compose file. The controller
sends names and placeholders only. Literal values cannot override a declared
secret. Secrets require a managed primary image; companions do not receive them.

`local_bearer_env: BROKER_TOKEN` selects one declared secret for authenticated
broker tunnel dispatch to that primary runner. The agent replaces the request's
Authorization header locally and refuses redirects. Public HTTP edge traffic
does not receive this credential. Attach documents and apply reports omit it.
The resolved Compose file is private (0600); it contains startup secrets and
must be handled like the enrollment credentials.

Normal restarts reuse the stored values. Corrupt records, missing recorded keys,
or a missing record with an initialization marker stop reconciliation before
new containers/routes are installed. Restore the entire secret directory,
including markers, together with encrypted runtime journal volumes; generating
replacement keys cannot recover an existing encrypted journal. Stop and removal
retain secrets and volumes. Never start a second restored copy of an enrollment.
